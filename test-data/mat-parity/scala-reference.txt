# Rows are:  <n> <case> <hex>
# where <hex> is the raw 64-bit IEEE-754 pattern of the result, never decimal
# text -- what is pinned here is the floating-point ASSOCIATION ORDER of
# Mat.sumD (8 unrolled accumulators combined as ((s0+s1)+(s2+s3))+((s4+s5)+(s6+s7)),
# then min(MaxSumChunks=16, n/4096) chunks combined sequentially), and a
# tolerance would wave through exactly the drift this catches.
#
# INPUTS are not carried here; both sides rebuild them from NumPyRNG, which is
# already bit-identical across the port:
#
#   let rng = NumPyRNG(20260814)
#   x(i) = if i even then rng.uniform(-1e6, 1e6) else rng.uniform(-1e-6, 1e-6)
#
# drawn ONCE to the largest size, with every smaller size taking a prefix.
# Magnitudes alternate so that reassociating the sum actually moves the result;
# math.sin was rejected as a generator because the JVM and Rust may round it
# differently in the last ulp, which would fail this fixture for the wrong reason.
#
